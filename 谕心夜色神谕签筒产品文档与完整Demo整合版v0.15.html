08

交互与反馈规范

  • 零僵尸按钮：一切视觉可点元素必有反馈——切页 / toast / 动画三选一；没有真实动作的入口不做成按钮。
  • toast 就近：反馈气泡绑定在被点击手机内（1.8s 自动消失），不串屏；文案统一「演示中 · ……」标注未开发功能。
  • 求签节奏：写心事 → 选仪式 → 「求一签」→ 摇签动画 1.6s → 结果三件套；节奏恒定，不做一键直出，保仪式感。
  • 好运值机制：按 06 章规则累加，驱动身份成长；不在任何界面直接售卖好运值。
  • 主题一致性：全 App 单一深金「夜色神谕」主题；后续主题皮肤只换 CSS 变量，不动架构。

11

AI 大模型接入设计 · 提示词与返回约束

谕心的今日签、问事三仪式结果与树洞回响，均由大模型实时生成。总原则不变：不预测结果，只陪你把选择想清楚——所有模型输出都是情绪陪伴式表达，并且必须通过三道闸：提示词硬约束 → 返回 JSON 结构化校验 → 内容安全兜底。

  • 三道闸：① Prompt 写明角色与红线；② 强制 JSON 返回并做 Schema 校验（缺字段 / 超长 / 含违禁词一律拒收）；③ 校验失败或模型不可用时回退到本地内置语料库，保证功能不中断。
  • 兜底语料：每类场景预置 5 组以上本地签文 / 回响（现有 5 组签文即可作为抽签兜底），模型故障时按随机或日期轮换返回。
  • 隐私底线：树洞正文仅单次推理使用，不进入模型训练、不落库明文；发送前做脱敏（手机号 / 微信号 / 地址等正则移除）。

11.8 用户画像下发（个性化上下文）

个性化只做两件事：换个称呼、换个说法。今日签与问事三仪式共用同一段 profile 上下文，不重复采集、不因仪式不同而改动字段。

① 发什么、不发什么

字段示例值用途与边界
nick听风人只用于称呼，一次输出最多出现一次

不发的：手机号、openid、位置、设备号、真实姓名、精确生日、树洞历史正文、其他用户数据。互测评分不传双方画像，只传答案与情绪标签，避免画像影响评分公平。

② 组装方式与插点（同一段画像插在各仪式「输入：」的最后一行，格式统一）

用户画像：{nick}｜{zodiac}｜{mbti}｜口吻={tone}｜时段={model_ts}

③ 口吻映射（同一支签的三种说法，结论不变）

tone写法要求示例
direct先给结论，再给一句理由；不用比喻，句子要短今晚别做决定。先把利弊各写三行，明早再看。
soft先接住情绪，再给方向；允许一句「我懂」你现在有点累，这很正常。把利弊写下来，明早再看也不迟。
poetic多用意象，少用祈使句，结尾留白夜还没走完。把利弊交给纸，明早再交给光。

三种口吻的结论必须一致，只换说法不换判断——这也是一条校验：同一 qid 换 tone 重生成，yi / ji 不得改变。

④ 与三道闸的关系：画像只进 Prompt 层，JSON Schema 与本地兜底不变；兜底语料按 tone 分三档短句，画像缺失时用默认 soft 档。用户画像属自填信息，隐私政策里写明「仅用于称呼与语气，不用于模型训练、不用于对外分享」。

  • 会员专属差异：多一个短句字段（焚香 sub / 观星 sky）；解读放宽到 100 字、temperature 0.8、max_tokens 400；结果卡去水印，星图卡带星座连线可保存。

mutual互测记录、同频指数、双方画像摘要云函数发起人长期
rituals焚香 / 观星结果（含星座 key）云函数本人长期
orders会员订单与支付状态支付回调（云函数）仅云函数5 年（对账）
quota每日次数配额（问事 3 次等）云函数仅云函数90 天
sign_library签库 / 牌库 / 兜底语料（内容资产）运营后台所有人（只读）版本化
config开关、文案、模型参数版本运营后台所有人（只读）版本化
feedback用户反馈与建议本人运营1 年
events关键行为埋点（轻量）云函数仅云函数90 天

不建「一个大 users 集合装所有东西」的表。今日签、问事、焚香观星各自独立，原因是查询模式完全不同：一个是「按人按天取一条」，一个是「按人按时间倒序分页」，一个是「按类型取最近 N 条」。合成一张表会让索引失效。

字段类型说明

  • 合规：正文不进入模型训练、不进日志、不进埋点；risk=2 只记录标记，不记录触发词原文。

16.9 orders · 会员订单

字段类型说明

16.10 quota · 次数配额

字段类型说明
uidstring用户

签库（30 支）、牌库（12 张）、兜底语料（按 tone 三档）都放在 sign_library，一条一行，方便后台改一条不改全表。

  "text": "山重水复处，自有新路。", "yi": "慢一点", "ji": "冲动决定",
  "tags": ["迷茫", "转折"], "ver": 3 }

{ "kind": "tarot", "no": 9, "symbol": "隐", "name": "隐士",
  "word": "克制内省", "ori_allow": ["正位","逆位"] }

16.14 不该存的东西

  • 出生年份 / 精确生日：只存 "月-日"，星座本地算好。年龄不是产品需要的，存了就是风险。
  • 手机号、微信昵称原始串、头像 URL 原链：昵称用户可改、头像不落盘，只在会话内展示。
  • openid 明文下发前端：前端只需要一个会话态，所有身份判断在云函数里做。
  • 树洞正文进入模型日志、埋点、训练集：只传本次会话，出参不回传原文。
  • 支付卡号、身份证、位置、设备号：一个都不存；支付只留微信返回的 transaction_id。

16.15 容量与生命周期

按 1000 日活估算：今日签约 3.6 万条 / 年，问事约 20 万条 / 年（人均 0.6 次 / 天），树洞约 6 万条 / 年，焚香观星约 5 万条 / 年。单条文档都在 1KB 以内，一年总量不到 400MB，处于云开发免费额度内；真正需要控的是树洞密文与分享卡图片（走云存储，不占数据库）。

  • 冷热分离：treehole 超过 180 天迁到 treehole_cold（只读，仅在「往年今日」用到），主表保持轻。
  • 软删：树洞删除只置 deleted=true，7 天后由定时任务物理清；用户可在 7 天内恢复。
  • 导出：用户可一键导出自己的问事与树洞（JSON），这是合规要求的「数据可携带」。
  • 备份：每周一次全量导出到云存储归档，保留 4 份；误删可从备份恢复单集合。
