02 / TOOLING

工具与插件矩阵：六个环节，各挑一件

判断标准：能不能把"像不像"从主观印象变成可复现的数字。能，则纳入；只提供"更快写代码"但改变视觉的，一律排除。

环节工具 / 插件取舍在本项目怎么用
样式单一来源 tokens.json + WXSS 变量 采用 把原型 <style> 里的色值/字号/圆角/阴影/渐变/keyframes 全量导出为一张表，WXSS 只引用变量，杜绝"再目测一遍颜色"。这是设计令牌（Design Token）思路的直接移植。
单位换算 px→rpx 脚本（k=2.451） 采用 750rpx = 屏宽，原型屏宽 306px，故 1px = 2.4509rpx。批量替换而不是手抄，字号取整到 0.5rpx 以内。
端上截图 miniprogram-automator 采用 官方自动化 SDK，可驱动开发者工具模拟器做页面跳转、点击、输入、miniProgram.screenshot() 截图。只对模拟器负责，真机仍需人工抽查。
像素比对 pixelmatch / @devecorsoft/miniprogram-visual-test 采用 前者轻量、可配阈值；后者是现成的"小程序组件截图 + 像素级 diff"方案，直接接 Vitest/Jest。二选一即可，别两套并存。
预览与上传 miniprogram-ci 采用 命令行出预览码/上传版本，避免每次手动点开发者工具；配合 automator 可做"改完即刻回归"。
云函数部署 @cloudbase/cli（tcb fn deploy） 采用 当前最大阻塞：shareCode 与 getUnlimited 权限只在代码里，云函数没重传就等于没有。CLI 部署可脚本化、可回滚。
复杂动效 lottie-miniprogram 按需 只在"原型的 CSS 动画无法平移"时启用（例如需要沿路径变形）。代价是引入 JSON 资产与额外渲染层，能写 keyframes 就不要用它。
渲染引擎 WebView（默认） / Skyline 默认 WebView 原型重度依赖渐变、阴影、绝对定位与滤镜式质感，WebView 的支持面最接近浏览器；Skyline 更流畅但样式默认值与 Web 不同，需逐条显式声明。1:1 优先，性能二期再谈。
设计稿转码 Figma MCP / CodeBuddy / We0 类工具 本轮回避 这类工具适合"有 Figma 稿"的团队。你的源是已定稿 HTML，转码工具会重排图层、改写结构，反而破坏 1:1。
UI 组件库 Vant Weapp / TDesign 排除 任何组件库都自带圆角、阴影、间距语汇，一旦混用，页面就不再是原型那一套视觉。图标继续用内联 SVG。
工程化改造 weapp-tailwindcss / Taro / uni-app 排除 会改变类名、单位与构建产物，让"和原型逐行对照"失效。原生 WXML/WXSS 才是最短路径。
03 / CROSS-DOMAIN

跨领域借鉴：别只学同行，学"用数字管视觉"的行业

FLUTTER · 测试体系
Golden Test

把渲染结果存成基准图，每次改动跑一次像素比对，超阈值即失败。可搬的只有一句：不接受"我觉得差不多"，只接受 diff 数字。

WEB · 组件文档
Storybook + Chromatic

按"组件 × 状态"矩阵逐格截图存档，任何状态变化都能回溯。迁移：给每页建一张状态矩阵（会员/非会员、空/满、加载/结果），而不是只截一张默认态。

设计工程
Design Token

颜色、字号、间距只在一处定义，多端由脚本生成。迁移：tokens.json 作为唯一色值来源，WXSS 变量引用它，禁止在页面里写裸色值。

移动端原生
Snapshot Testing

基准图入版本库，随代码一起评审。迁移：把 23 张基准图与 diff 结果一起提交，让"视觉变化"出现在 diff 里，而不是靠人回忆。

影视 · 动画
Animatic（关键帧表）

先定关键帧节奏，再补插值，而不是"先做动效再调感觉"。迁移：签筒八拍、翻牌、燃香各自列出"第几帧、谁在动、动多久"，逐帧截图对。

制造业
首件检验 FAI

第一件做全尺寸检查，通过后才允许批量。迁移：先用首页把"字号/间距/圆角/阴影/状态栏"全部校到零差异，其余 13 页复用同一套规则批量推进。

04 / CONSTRAINTS

1:1 的物理约束：这六件事必须先承认

这些不是"可以努力一下"的问题，是不解决就一定露馅的地方。把它们写进提示词，才不会在中期返工。

4.1 单位与高度

原型（px）小程序（rpx）原型（px）小程序（rpx）
屏宽 306750字号 11.528
机身 padding 1024.5字号 1332
机身圆角 3893字号 18（标题）44
屏圆角 3073.5屏高 640不写死

关键判断：原型 640px 高只为"手机壳演示"服务；真机 844 逻辑高减去状态栏与 tabBar 后，可用区与 640px 的比例不同。因此内容区必须 flex:1 + min-height，而不是复制 640。

4.2 字体：最容易被忽略的一处失真

原型标题用 'Songti SC'（宋体），iOS 有、多数 Android 没有，会静默回退成黑体——整页气质当场变味。必须 wx.loadFontFace 加载思源宋体（云存储或 CDN，注意体积与首次加载延迟），并保留 serif 兜底；首屏字体未就绪时用 font-display 等价策略避免跳字。

4.3 组件层级：textarea 会盖住一切

问事页与树洞页都用大文本框。小程序 textarea 是原生组件，层级高于普通 view，弹层、toast、确认框会被它穿透覆盖。这是"功能一样但体验不一样"的典型：要么改用 input 分多行拼，要么在弹层出现时临时隐藏 textarea。

4.4 动画载体换了

原型星轨靠 SVG stroke-dashoffset 描线，小程序没有 SVG 元素。这个效果必须换载体：canvas 2D 画点与线（按原时序逐段推进），或预渲染成序列图。不能"删掉不做"，那是原型最抓眼的一处动效。

4.5 系统件避让

原型自绘「21:41 / 谕 / 晚安」状态栏，真机上会有真实状态栏与右上胶囊。必须取 statusBarHeight 与 menuButton 位置，把自绘状态栏放在其下方，并保证右下不压胶囊。

4.6 云侧真的通了吗

22 个 action 齐备只是"代码写了"。要让"功能一模一样"，还需：8 个集合真实建立并配索引、云函数重传（含 wxacode.getUnlimited 权限）、shareCode 返回的真码能贴进卡面。否则分享卡永远停在占位框。

PROMPT · V1 定稿

你是「谕心」小程序的复刻工程师。任务：把一份已定稿的单文件 HTML 原型（14 个视图，含 canvas 分享卡与多段时序动画）1:1 还原为原生微信小程序（微信云开发，环境 id YOUR_CLOUD_ENV_ID，工程 E:\miniprogram\yuxin）。

【深度 · 原始数据与工具（先拿到，不许猜）】
1. 视觉真源唯一：谕心夜色神谕签筒完整可演示Demo.html。任何冲突以它为准；v0.15 文档与截图只作对照，不作改动依据。

【高度 · 结果（什么样才算完成）】
1. 逐页像素差报告：14 视图 × 关键态（会员/非会员、空/结果、引导 1-3），单页差异像素 < 2%，且每条差异都写明原因与处置。
2. 动效对齐表：每个动效的时长、缓动、触发点与原型一致；每个动效至少 3 帧截图对照。

4. 真机三机型：iOS 大屏、Android 中屏、窄屏（逻辑宽 320），排版不破裂、字体不回退成黑体。
5. 交付物：可编译工程 + 视觉回归脚本 + 差异报告 + README（含云函数部署与集合建立步骤）。

【广度 · 动作（按序，每步有产出与卡点）】
A1 冻结基线：确认原型校验和与 23 张基准图版本，记录在 README。
A2 抽 tokens：生成 tokens.json 与 px→rpx 对照表，输出《视觉规格表》。
A3 骨架校准：自定义导航 + 状态栏/胶囊避让 + 安全区 + custom tabBar，先让首页整页零差异。
A4 逐页复刻：按 01→23 顺序，「写 → 截图 → pixelmatch → 修」，该页不达标不进下一页。
